## T001 — Chronos theme reskin (JSON theme + theme.rs bridge) — DONE, committed

Implemented the first T-ticket in Chronos-FM: unified the old flat `theme.rs`
`u32` consts with gpui-component's live `Theme` engine, with dark/light.

Deliverables (commit `ui : chronos.theme.json + theme.rs bridge (dark/light,
unified with gpui-component) (T001)`):
- `script/dev/gen_chronos_theme.py` — seed-driven generator; ~140 keys/theme
  from fixed lightness/mix/alpha rules (not hand-picked).
- `crates/chronos-fm/assets/themes/chronos.theme.json` — `Chronos Dark` /
  `Chronos Light`, embedded via `include_str!`.
- `crates/chronos-fm-ui/src/theme.rs` — bridge: each `const NAME:u32` →
  `fn name(cx:&App)->Hsla { cx.theme().<field> }`. `TOOLBAR_*` mapped to
  nearest `ThemeColor` (sidebar/list_active) with comments.
- `crates/chronos-fm/src/app.rs` — `activate_chronos_theme()`: loads JSON into
  `ThemeRegistry`, sets `Theme.light_theme/dark_theme`, re-calls `Theme::change`.
- 19 consumer files mechanically edited (`rgb(theme::X)` → `theme::x(cx)`).

Verified: `cargo build --workspace` clean (0 err, 0 our-code warns),
`cargo test --workspace` 171 pass / 0 fail.

### Key pitfalls (reusable)
- **Accent hard rule**: seed `accent.primary` = `#007acc` in BOTH modes.
  `ThemeColor` has `accent` but NO `accent_hover`. Bug fixed: generator had
  set `c["accent"] = accent_h` (Mocha mauve `cba6f7`) — must be `c["accent"]
  = accent` (007acc). Mauve seed → `magenta` instead.
- **`_cx` params**: many render fns name the app ctx `_cx`; patch emitted
  `theme::x(cx)`. Fix = rename `_cx`→`cx`, or (inside closures) use `_cx`.
- **Closure escape (E0521)**: `move` closures stored in menus (`'static`)
  cannot capture `&App`/`&mut Context`. Hoist `Hsla` values out of the closure
  first (e.g. `let c = theme::fg(_cx);` then capture `c`).
- **`rgb()` returns `Rgba`**, bridge returns `Hsla` → use `hsla(0.,0.,1.,1.)`
  for white/black, not `rgb(0xFFFFFF)`.
- **Tests need `gpui_component::init`**: `cx.theme()` panics in unit tests
  without it. Add `cx.update(|app| gpui_component::init(app));` before draw.
- `gpui::Context<T>` derefs to `App`, so bridge fns taking `&App` accept
  `&mut Context<T>` / `&mut Window` via coercion.

### Constraints honored
- Did NOT touch `Source/gpui-component` (read-only dep) or `docs/agents/active/b1..b4`.
- Live GUI pipette run not possible in headless env — verified embedded hex
  against seed §2 programmatically; noted in report for architect's live check.

`compile_error!("You can't enable both async-io & tokio features at once")`.

`ashpd/async-io`, AND `gpui_linux` (secret feature) → `oo7` → `ashpd/tokio`.
Feature unification enables both. Reproducible at clean HEAD (`git stash -u` +
`cargo check -p chronos-fm`). NOT introduced by my changes.

(pages + binary). So pages-crate test edits (properties.rs) and any GUI
measurement (T014) are UNVERIFIABLE in this env — must be done on architect's
machine. `chronos-fm-services` compiles fine (no gpui_linux dep). This is a
separate blocking issue for the architect, outside T013/T014/T016 scope.
Documented in T016/T013/T014 reports.

## T016 — search survives unreadable $HOME subdirs — DONE, committed `459ea2b`

P1 bug: `notify` recursive watch aborted on one `PermissionDenied` subdir
(podman volume UID 100999), killing whole SearchService silently.
Fixes (all in `chronos-fm-services`, verified by `cargo test`):
- NEW `search/exclusions.rs`: `Excludes{paths,globs}`;
  `DEFAULT_EXCLUDE_COMPONENTS` (containers, node_modules, target, .git, .cache,
  .gvfs, .cargo, .npm, .rustup, .Trash); `from_config()`; `matches()` (component
  deny-list + abs prefix + rel component + glob `**`). 4 tests.
- `watcher.rs`: `FileWatcher::new(root,tx,timeout,excludes)` — try Recursive
  watch; on failure fall back to `ignore::WalkBuilder` + `filter_entry(move|e|
  !excludes.matches(e.path()))`, watch each readable dir NonRecursive, swallow
  `PermissionDenied`. Test `watcher_survives_unreadable_subdir` (`#[cfg(unix)]`,
  root-skip via chmod 000).
- `indexer.rs`: `IndexManager` carries `excludes`; both walks `filter_entry`.
  Test `index_home_tolerates_unreadable_subdir`.
- `engine.rs` / `app.rs`: `SearchService::new(excludes)`; feeds
  `config.indexing.exclude` into `Excludes::from_config` (wires the previously
  unwired `[indexing.exclude]` config). `search_bar.rs`: UI warning
  `⚠ Full-text search unavailable` when `page.search_service.is_none()`.
- `properties.rs` recursive-size loop & `fs/ops.rs copy_tree` already tolerant —
  no change. Report: `T016-search-service-report.md`.
