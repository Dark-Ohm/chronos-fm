# T017 — Отчёт: Git-панель не следует за Explorer (follow-режим мёртв)

**Статус:** выполнено (корень установлен + код + юнит-тесты).
**Приоритет:** P1. Приёмка — архитектор лично (живой прогон по шагам
«Симптом»).

## Корень (установлен по коду)

Гипотеза из тикета подтверждена, плюс найдено следствие-обострение.

**1. Луп просыпается, но refresh не вызывается.** `start_refresh_loop`
(`git.rs:132`) каждые 400 мс делает `rx.try_recv()`, и **только** при
`changed == true` (сигнал из канала) зовёт `page.refresh(cx)`. Единственный
источник сигнала — `refresh_tx`, который шлёт `GitWatcher` — наблюдатель
за содержимым `.git` **уже открытого** репозитория (HEAD, index, refs).
Навигация Explorer в этот канал ничего не отправляет: `PaneEvent::Navigated`
эмитится панелью (`navigation.rs:159/211/239/254`) и обрабатывается
внутренним `ExplorerPage::on_pane_event` (mirror-sync + session save), на
который GitPage не подписан. Поэтому `current_path` перечитывается только
внутри `refresh()`, который без сигнала не выполняется никогда.

**2. Следствие:** выход из репозитория оставляет устаревший статус — это
тот же корень (refresh не сработал), а не отдельный баг: ветка
`NotARepository` в `do_refresh` корректно обнуляет `status`/`no_repo` и
сбрасывает watcher, но до неё никто не доходит.

## Что сделано (один файл: `git.rs`)

### 1. Луп теперь отслеживает смену директории (follow-режим)

Выбран вариант из тикета «перечитывание `current_path` в самом лупе» —
самодостаточен, ложится на существующую 400 мс архитектуру и одинаково
обрабатывает вход и выход из репозитория (подписку на `PaneEvent` не
делаем: она потребовала бы кросс-сущностного проброса от `ExplorerPage`,
который держит панели в себе).

- Новое поле `last_dir: Option<PathBuf>` — директория последнего refresh.
- Каждый тик лупа: `page.current_dir(cx)` сравнивается с `page.last_dir`; при
  расхождении (или при `changed` от watcher) — `page.refresh(cx)`.
- `refresh()` фиксирует `last_dir` на старте, поэтому он синхронен со всеми
  путями refresh: первичный, кнопка, луп, stage/unstage/commit, pin/unpin.

Поведение:
- Заход в репозиторий → следующий тик (≤400 мс) → refresh → панель
  наполняется **без** Refresh.
- Выход → `NotARepository` → пустое состояние **без** Refresh.
- Внутри одного репозитория (смена поддиректории) refresh пересчитывает
  тот же workdir — лишней работы нет, статус тот же.

### 2. Pin не ломается

При пине `current_dir` всегда возвращает закреплённый путь, `dir == last_dir`
каждый тик → луп не дёргает refresh по смене директории; обновления идут
только по сигналу watcher'а закреплённого `.git`. `toggle_pin` (обе стороны)
и так вызывает `refresh()` явно.

### 3. Гонка устаревших результатов закрыта (generation-счётчик)

Следствие правки: refresh теперь запускается на **каждую** навигацию
(раз в тик), а `do_refresh` применял результат асинхронного чтения
безусловно. При быстрой навигации A→B→A два чтения могли завершиться не в
том порядке, и старый статус перезаписал бы новый. Добавлен
`refresh_generation: u64`, инкрементируемый в начале `do_refresh`; результат
спавна применяется только если `refresh_generation` не изменился — иначе
отбрасывается целиком (флаг `refreshing` принадлежит более новому чтению).
Цена — один счётчик и одно сравнение.

### 4. Логика выбора пути вынесена в свободные функции (для юнит-тестов)

- `resolve_follow_dir(pinned, explorer_path)` — pin приоритетнее, иначе
  путь активной вкладки Explorer.
- `should_refresh(changed, follow_dir, last_dir)` — решение лупа:
  сигнал watcher ИЛИ смена follow-директории.
