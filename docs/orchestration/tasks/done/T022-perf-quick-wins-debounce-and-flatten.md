## Откуда взялись эти два варианта

Perf-замер T014 (3 × 10 с, `perf -F 1000 -g`, release с символами, на
живой машине 2560×1440 @ 144 Гц) дал:

| Режим | Что жрёт |
|---|---|
| Покой | `taffy` ~40 %, debouncer `notify-rs` **~30 %**, futex/mutex ~15 % |
| Скролл | `taffy` **~70 %**, создание новых taffy-нод ~10 %, malloc ~10 % |
| Hover | `taffy` ~65 %, ротация text-cache ~15 %, hit-testing ~5 % |

Отчёт предложил четыре варианта; архитектор выбрал **D + C** —
наименьший риск при осязаемом выигрыше. Варианты A (layout memoization
в форке gpui) и B (reuse taffy-нод) в этот тикет **не входят**.

## Часть D — debounce файлового watcher'а

**Где:** `crates/chronos-fm-services/src/search/engine.rs:100`

```rust
let watcher = FileWatcher::new(home_dir, tx, Duration::from_secs(2), excludes)?;
```

Фоновый поток debouncer'а хеширует пути (`hash<PathBuf>`,
`write<Sip13Rounds>` в профиле) и в покое съедает около 30 % CPU —
при том, что окно в это время может вообще ничего не делать.

**Что сделать:**
1. Поднять таймаут (отчёт предлагает 2 с → 5 с). Значение вынести в
   константу с комментарием, а не хардкодить второй раз.
2. Рассмотреть второй рычаг из отчёта: приостанавливать watcher, когда
   окно не в фокусе. Это даёт больше, чем таймаут, но требует сигнала
   о фокусе из UI-слоя — оценить стоимость и **либо сделать, либо явно
   отказаться в отчёте**, не умалчивая.

**Цена:** индекс поиска обновляется реже. Это сознательный размен, его
надо назвать в отчёте, а не подать как чистый выигрыш.

## Часть C — уплощение дерева элементов

**Где:** `crates/chronos-fm-pages/src/explorer/view.rs`,
`.../view/listing/list.rs`, `.../listing/row.rs`, `.../listing/grid.rs`,
`.../view/sidebar.rs`

GPUI перестраивает всё дерево каждый кадр: каждый элемент →
`request_layout()` → новый taffy-нод → полный пересчёт flexbox → в
конце `layout_engine.clear()`. Меньше вложенных `div` — меньше нод.
Отчёт оценивает выигрыш в 15–25 % нод.

**Что сделать:**
1. Пройти по перечисленным файлам и убрать обёртки-`div`, не несущие
   ни стиля, ни layout-смысла (частый случай — `div().child(div()...)`,
   где внешний только прокидывает потомка).
2. Батчить `cx.notify()` там, где за один пользовательский жест
   вызывается несколько подряд.
3. **Не менять внешний вид.** Это рефакторинг, а не редизайн; любое
   визуальное отличие до/после — дефект этого тикета.

**⚠ Коллизия по файлам (обновлено 2026-08-07):** T019 закрыт, но он уже
правил `sidebar.rs` (эллипсис пути) — сверяться с текущим состоянием
файла, а не с досессионным. Остаток **T015** (высота карточки Places)
всё ещё делит с частью C тот же файл: одному исполнителю либо строгая
очередь.

Причина строгости — не теория: 2026-08-06 параллельный агент писал в
файл между моим `Edit` и `git mv`, а 2026-08-07 я сам `git add`-ом по
каталогу утащил в свой коммит чужой незакоммиченный каталог `hold/`.
**Стейджить пофайлово, не по каталогу.**

**Заодно, раз часть D трогает `search/engine.rs`:** там же есть
предсуществующий баг соседства — при втором запущенном экземпляре
приложения индекс отваливается с `LockBusy`, а KV-store с

бинаря при замере — знай, что второй будет без поиска.

## Обязательный замер

Тикет-родитель T014 завёл правило «не оптимизировать до цифр». Оно
остаётся в силе и для проверки результата.

```bash
# сборка с символами — БЕЗ этого стек в perf будет пустой
CARGO_PROFILE_RELEASE_DEBUG=1 CARGO_PROFILE_RELEASE_STRIP=none \
  cargo build --release -p chronos-fm

perf record -F 1000 -g -p $(pidof chronos-fm) sleep 10   # ×3 режима
perf report --hierarchy
```

**Ловушка, стоившая захода 2026-08-06:** голый `cargo build --release`
бинарь **не собирает** — GUI-крейты вынесены из `default-members` в
корневом `Cargo.toml`. Команда завершится «Finished» за секунды, оставив
старый артефакт, и замер уйдёт в него. Обязателен `-p chronos-fm`;
перед прогоном сверить `stat -c '%y' target/release/chronos-fm` с mtime
изменённых исходников.

Замер в трёх режимах — покой / скролл / hover, на папке ~114 items,
как в исходном замере T014. Иначе цифры не сопоставимы.
