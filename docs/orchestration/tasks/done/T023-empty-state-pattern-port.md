## Суть задачи

Как и в ChronOS, визуальный язык карточек уже унифицирован — T002
(`elevated_card`/`section_header` в `crates/chronos-fm-ui/src/patterns.rs`,
аналог ChronOS T231). Не зафиксировано единое решение «**что показывать,
когда данных нет/мало**» — оно и есть предмет этого тикета. Решение
портируется из ChronOS T252, адаптируется под страницы этого репо.

## Что нужно — этап 1 (решение, как в T252)

1. Прогнать **единый чек-лист из 6 классов отсутствия** (ChronOS T252,
   ratified) по всем страницам `crates/chronos-fm-pages/src/**`
   (explorer со своими под-вью: listing/sidebar/preview/search; settings;
   git; s3; extensions):

   1. **Вся страница пуста / покоящееся состояние** → честный
      плейсхолдер: что отсутствует и (где уместно) куда идти.
      Центрированный блок, если страница «по сути пуста»; inline
      muted-строка внутри карточки, если остальная часть полезна.
   2. **Под-секция пуста внутри заполненной страницы** → компактная
      inline muted-строка/CTA, НЕ гигантский плейсхолдер.
   3. **Асинхронная загрузка не завершена** → центрированный «Loading…»,
      а не финальный empty до оседания фона.
   4. **Ошибка / источник недоступен** → сообщение цветом `danger`/
      `status.error` с КОНКРЕТНОЙ причиной. Никогда пустой прямоугольник,
      никогда генерик «error».
   5. **Усечение / мягкие лимиты** → честный баннер («Showing N of M
      (limit L)» и т.п.), без тихого обрезания.
   6. **Не реализовано** → иконка + имя + что будет, БЕЗ ETA и БЕЗ
      «coming soon».

   Плюс два сквозных правила T252: **честность §13** (никакого
   фейкового контента, каждая ошибка несёт причину) и техника
   **`min_h`-пола карточки** (T249) для короткого контента, чтобы не
   оставалось «голой пустоты» снизу.

2. Для каждой страницы зафиксировать: что показывается при отсутствии
   данных и **почему именно так** (свернуть? заглушка? резерв места?).

3. Записать решение как паттерн + блок «Решение» в этом тикете.
   **Механизм (решено 2026-08-07): оба варианта.** Завести
   `docs/DECISIONS.log` по образцу ChronOS (основной журнал; решение
   T023 — первая запись) И оформить короткую запись как **ADR 0010** в
   `docs/adr/` (для тех, кто ищет решения в adr/). Остальные пробелы
   порта рабочих паттернов — отдельным тикетом **T024**.

4. **Насильственный хелпер НЕ вводить**, если случаи осознанно разные —
   это главный вывод T252 (центрированный блок vs inline vs баннер vs
   error сломались бы общим хелпером). Кодовая унификация inline
   muted-строк — **отдельной задачей**, только если найдётся ≥3 сайтов
   с каноничным стилем (`px(12) py(9) rounded_md border subtle muted`).

## Предварительная карта (быстрый греп 2026-08-07 — сверить аудитором)

| Страница | Что показывается при отсутствии данных | Класс |

| explorer — preview | плейсхолдер-заглушка (`view/preview.rs:8`) | 1 |

| extensions | «No plugins configured. Add them in config.toml:» + TOML-сниппет внутри `elevated_card` (проверено живьём, T012) | 1 |

Открытые вопросы аудита (примеры, не исчерпывающе):

- `git.rs:431` — пустые под-секции скрываются молча. Это осознанно
  приемлемо (заголовок секции сам говорит о пустоте) или нужна
  компактная inline-строка по классу 2?
- Есть ли страницы с контентом короче вьюпорта, где нужен `min_h`-пол

  показывается пользователю (T016 фиксил падение, но UX пустого поиска
  не пересматривался)?
