# T016 — Поиск отключён целиком из-за одной нечитаемой поддиректории в $HOME

**Приоритет:** P1 — полнотекстовый поиск сейчас **не работает вообще**,
молча. Для цели «не хуже Dolphin» это дыра, а не косметика.
**Статус:** баг с установленным корнем, готов к исполнению.
**Источник:** живой прогон релизного бинаря 2026-08-06, лог запуска.

## Симптом

При старте приложения в логе:

```
ERROR chronos_fm::app: Failed to initialize search service; starting with
search disabled: Permission denied (os error 13) about
["/home/neo/.local/share/containers/storage/volumes/hindsight-data/_data/instances/hindsight/data"]
```

Приложение продолжает работать, но **поиск выключен полностью**. Наружу
это никак не сообщается — только строка в логе, которую пользователь не
видит. Пользователь думает, что поиск просто не находит.

## Корень (установлен по коду, не гипотеза)

1. `app.rs:91` — `SearchService::new()` возвращает `Err` → сервис не
   создаётся, дальше всё приложение живёт с `search_service: None`.
2. `search.rs:52-55` → `engine::SearchEngine::new()?`.
3. `search/engine.rs:97-99` — `dirs::home_dir()` и
   `FileWatcher::new(home_dir, tx, 2s)` — watcher вешается на **весь
   `$HOME`**.
4. `search/watcher.rs:39` — точка отказа:
   ```rust
   debouncer.watcher().watch(&root, RecursiveMode::Recursive)?;
   ```
   Рекурсивный обход натыкается на podman-volume:
   ```
   drwx------ 1 100999 100999 .../hindsight-data/_data/instances/hindsight/data
   ```
   Каталог принадлежит UID `100999` (userns-маппинг контейнера), режим
   `0700` — обычный пользователь его прочитать не может. `notify`
   возвращает `PermissionDenied`, `?` пробрасывает ошибку вверх, и
   **весь** поиск умирает из-за одной чужой директории.

**Суть дефекта архитектурная:** в `$HOME` любого живого пользователя
рано или поздно появляется что-то нечитаемое (контейнеры, gvfs/fuse-
маунты чужих uid, `.gnupg`, сломанные симлинки, docker/podman volumes).
Индексатор обязан такие ветки пропускать, а не отказываться работать.

## Что нужно

1. **Watcher не должен падать целиком.** Нечитаемая поддиректория —
   пропустить (лог `debug`/`trace`, не `error`) и продолжить. Проверить,
   что даёт `notify` в этом сценарии: если рекурсивный `watch` на корне
   не умеет частичный отказ, watch'ить ветки по мере обхода и глотать
   `PermissionDenied` на каждой отдельно.
2. **Индексатор — так же.** `index_home` (`engine.rs:32/45/59`) должен
   переживать `PermissionDenied`/`NotFound` на отдельных записях (в т.ч.
   гонку «файл удалили во время обхода»), а не прерывать индексацию.
3. **Исключения по умолчанию.** Завести список пропускаемых путей, чтобы
   не молотить заведомо чужое и тяжёлое: `~/.local/share/containers`,
   `~/.cache`, `.git`-объекты, fuse/gvfs-маунты, `node_modules`,
   `target/`. Решить, из конфига это или хардкод (в `config.toml` уже
   есть секция `ui`/`explorer` — возможно, нужна `search`).
4. **Отказ должен быть виден в UI.** Если поиск всё-таки не поднялся —
   не молчать: пометка в поисковой строке/статус-баре, а не только
   `tracing::error`. Молчаливая деградация — половина этого бага.
5. **Проверить, не тот же ли дефект в других рекурсивных обходах:**
   `properties.rs` (рекурсивный размер папки), `fs::ops` (copy/delete
   дерева) — падают ли они на нечитаемой поддиректории целиком.

## Тесты (обязательны, юнитом — этот баг воспроизводим без GUI)

- Временное дерево (`tempfile`) с поддиректорией `0000` (или
  `chmod 000` на unix) → `FileWatcher::new` **не** возвращает `Err`,
  остальное дерево watch'ится.
- Индексация такого дерева → доступные файлы в индексе, недоступная
  ветка просто отсутствует, ошибки нет.
- Тесты пометить `#[cfg(unix)]` (права), под root они бессмысленны —
  предусмотреть skip.
