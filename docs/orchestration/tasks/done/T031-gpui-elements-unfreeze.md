# T031 — Форк: расконсервировать `gpui_elements`

> ## ✅ ARCHITECT VERDICT: **CLOSED** (2026-08-09)
>
> Unfreeze investigation → **delete crate**. Not used; 6× API drift to
> gpui-ce. Source commit `fa2d64f`. Report:
> `report-log/T031-gpui-elements-unfreeze-report.md`.

**Приоритет:** P3 — ниже остальных: крейт сейчас никому не нужен, но он
единственный **зафиксированный** случай API-дрейфа между форком и
вендоренным кодом, и потому полезен как мерка расхождения.
**Скоуп:** `Source/`.

## Что законсервировано

`Source/Cargo.toml:31-33`, комментарий в самом манифесте:

```
# gpui_elements: excluded — v0.1.0, has 7 API-drift errors (ActionBindingCollection,
# TextLayout methods, is_nearly_eq missing in Source/gpui). Not referenced by any
# other crate. Re-enable when Source/gpui API catches up.
```

Три названных расхождения: `ActionBindingCollection`, методы
`TextLayout`, отсутствующий `is_nearly_eq`.

## Что сделать

1. Вернуть `"gpui_elements"` в `members` и получить **актуальный** список
   ошибок: комментарий писался давно, форк с тех пор двигался, и часть
   могла закрыться сама. Начать с фактов, а не с комментария.
2. По каждой ошибке — вердикт, а не сразу правка:
   - **дрейф в сторону крейта** — крейт зовёт API, которого в нашем gpui
     не было и не будет; чинится в крейте;
   - **пробел в форке** — API есть в апстриме gpui и осмысленно у нас
     (`is_nearly_eq` пахнет именно этим); чинится в форке;
   - **мёртвый код** — крейт использует то, от чего мы сознательно
     отказались; тогда вопрос не «как починить», а «нужен ли крейт».
3. Починить только первую и третью категории. Вторая — **отдельный
   тикет**, см. стену.

## Стены

**Стена 1 — правки в `Source/gpui` здесь запрещены.** На нём висят
ChronOS, greeter Chronos-lm, Chronos-FM, Chronos-IDE. Если вердикт по
ошибке — «пробел в форке», работа по ней **останавливается** и уходит в
отдельный тикет с обоснованием. Соблазн дописать один метод в gpui,
чтобы закрыть строку, — это ровно тот случай, когда чинится один крейт и
ломаются четыре проекта.

**Стена 2 — «7 ошибок» это цифра из комментария, а не измерение.**
Первое, что должно быть в отчёте, — фактический вывод компилятора
сегодня. Если их три или двенадцать — так и писать.

**Стена 3 — крейт может оказаться не нужен.** Он ни на что не ссылается.
Валидный исход тикета — «расконсервация стоит дороже, чем крейт стоит;
предлагаю удалить», с перечнем ошибок как обоснованием. Это не провал.

**Стена 4 — базовые линии.** Даже при правках только внутри
`gpui_elements` возврат крейта в `members` меняет резолв воркспейса. До
и после:

```bash
cargo check --workspace --manifest-path ChronOS/Cargo.toml
cargo test  --workspace --manifest-path Chronos-FM/Cargo.toml   # эталон 294 passed
```
