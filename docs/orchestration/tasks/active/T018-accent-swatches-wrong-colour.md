# T018 — Свотчи accent-цвета рисуются неверным цветом (rgba вместо rgb)

**Приоритет:** P2 — пикер акцента визуально сломан целиком: ни один из
семи цветов не соответствует палитре, два практически невидимы.
**Статус:** баг с установленным корнем, правка однострочная.
**Источник:** живой смок релизного бинаря 2026-08-06, приёмка T009.

## Симптом

Settings → Theme → Accent: семь свотчей отрисованы в оттенках тёмно-синего
и зелёного. Оранжевого, красного и розового нет вовсе. При `accent = "purple"`
в `config.toml` выбранный (обведённый рамкой) свотч — **зелёный**.

## Корень (установлен по коду, подтверждён попиксельно)

`crates/chronos-fm-pages/src/settings.rs:100`:

```rust
let fill = gpui::Hsla::from(gpui::rgba(color.rgb));
```

`gpui::rgba()` принимает `0xRRGGBBAA` (8 hex-цифр), а `ACCENT_PALETTE`
(`crates/chronos-fm-core/src/config/settings.rs:122`) хранит 6-значные
`0xRRGGBB`. Значение сдвигается на байт: красный канал всегда `0x00`,
зелёный получает бывший красный, синий — бывший зелёный, альфа — бывший синий.

Совпадение с наблюдаемым — по каждому цвету:

| Палитра | Как читает `rgba` | Что видно |
|---|---|---|
| `blue 0x007acc` | R=00 G=00 B=7a A=cc | тёмно-синий |
| `green 0x00a86b` | R=00 G=00 B=a8 A=6b | полупрозрачный синий |
| `purple 0x8b5cf6` | R=00 G=8b B=5c A=f6 | зелёный (выбранный) |
| `orange 0xe8930c` | R=00 G=e8 B=93 A=0c | почти невидим |
| `red 0xdc2626` | R=00 G=dc B=26 A=26 | тёмно-зелёный |
| `teal 0x0d9488` | R=00 G=0d B=94 A=88 | синий |
| `pink 0xdb2777` | R=00 G=db B=27 A=77 | полупрозрачный зелёный |

Внесено коммитом `f0ab77e` (accent-пикер, follow-up к T009). Тестами не
ловится: цвет свотча нигде не ассертится, покрыт только `accent_hex()`.

## Что нужно

1. Заменить `gpui::rgba(color.rgb)` на `gpui::rgb(color.rgb)` —
   6-значный непрозрачный конструктор.
2. Проверить остальные вызовы `rgba(` в UI-крейтах на ту же ошибку:
   `rgba` с 6-значной константой всегда означает потерянный красный
   канал и мусорную альфу. Грепнуть `rgba(0x` и сверить длину литералов.
3. Проверить, что `hover_border` (`0xffffff99`, `settings.rs:102`) —
   действительно 8-значный и менять его не нужно.

## Тесты

Добавить юнит, сверяющий, что цвет свотча соответствует
`ACCENT_PALETTE[i].rgb`: `Hsla::from(rgb(x))` → обратно в `Rgba` →
сравнить каналы. Иначе баг вернётся молча — как и вернулся сейчас.
