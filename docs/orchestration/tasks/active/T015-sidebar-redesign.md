# T015 — Сайдбар: убрать мёртвый блок, свести «Места» и «Устройства» к одному ритму

**Приоритет:** P2 — не ломает функционал, но это первое, что видит глаз,
и сейчас оно выглядит как три несвязанные карточки друг под другом.
**Статус:** ТРЕКИНГ-ТИКЕТ — сначала брейншторм по дизайну, потом код.
**Источник:** живой прогон 2026-08-06 (скриншот `/home/neo`), оценка
пользователя: «зачем два блока быстрого доступа? новый блок
umount+favorites сломали всю эстетику файлового менеджера, их надо
красиво было вставить».

## Что не так — по коду, а не по ощущению

`crates/chronos-fm-pages/src/explorer/view/sidebar.rs`:

1. **Верхний блок целиком мёртвый** (строки 28-31): `Home`, `Favorites`,
   `Recent`, `Trash` рендерятся через `sidebar_item()`, у которого
   **нет `on_click` вообще** (`sidebar.rs:42-61`) — только `hover`.
   Четыре кнопки, ни одна не работает.
2. **Дубль `Home`**: он и в мёртвом верхнем блоке, и в рабочей карточке
   `Folders / quick access` (`render_shortcuts` → `change_dir`,
   строки 63-104). Живой — только второй.
3. **Три карточки подряд** (`Places`-обманка → `Folders` → `Devices`,
   строка 39) — сайдбар растёт вниз пачкой контейнеров без общего ритма.
   Devices (T003/T008) прилепился четвёртым ярусом, отсюда ощущение
   «сломанной эстетики» — сама секция не виновата, виновата композиция.
4. **`unmount` / `eject` — сырой текст** (`sidebar.rs:237-243`,
   `286-292`): `text_xs` + `muted`, без фона/рамки/иконки. Читается одной
   фразой «VTOYEFI unmount eject», не считывается как действия.
   Правый край упирается в границу карточки — на скриншоте `eject`
   обрезан впритык, у карточки нет правого padding под зоны.
5. **Дисбаланс кегля**: имя тома крупное, действия `text_xs` — действия
   визуально проваливаются.
6. **I/O в рендере**: `get_shortcuts()` (`sidebar.rs:106-132`) делает
   4 синхронных `Path::exists()` **на каждый рендер**. Кэшировать
   (пересчитывать по факту изменения, не покадрово). Пересекается с T014.

## Что нужно ПЕРЕД кодом

1. `brainstorming` skill — по правилу репо для любого UI-редизайна.
   Решить на дизайн-уровне:
   - Судьба мёртвых пунктов: `Favorites`/`Recent`/`Trash` — **реализовать
     или убрать**. Держать нерабочие кнопки в проде нельзя. Если
     реализовывать — это отдельные тикеты, не смешивать с редизайном.
   - Единый ритм секций: «Места» и «Устройства» одинаковой вёрсткой
     (одинаковые отступы, заголовки, высота строки), а не разнотипными
     карточками.
   - Подача действий тома: иконки по hover вместо текстовых меток,
     правый padding, чтобы ничего не упиралось в край.
   - Ориентир — Dolphin (цель проекта — паритет), но в своей
     design-системе (`chronos_fm_ui::patterns`, `theme`).
2. Design spec → `docs/superpowers/specs/`.
3. Implementation plan → `docs/superpowers/plans/`.
4. Только после этого — код.

## Верификация

- Живой прогон на релизной сборке + скриншот: ни одной нерабочей кнопки
  в сайдбаре, `unmount`/`eject` не упираются в край, секции читаются
  одним ритмом.
- Клик по каждому оставшемуся пункту реально навигирует (проверить
  вживую, не только юнит-тестом).
- `cargo test --workspace` зелёный.
