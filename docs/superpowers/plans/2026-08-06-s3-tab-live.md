### Task 4 — `S3FileSystemProvider` (trait impl)

**Crate:** `chronos-fm-services`  
**File:** `src/s3/provider.rs` (or inline in `src/s3/mod.rs`)  
**Lines:** ~150

1. Implement `FileSystemProvider` for `S3Client`:
   - `list_dir`: bucket listing at root, object listing at prefix level
   - `read_file`: get_object
   - `metadata`: head_object
   - `create_dir`: no-op (or zero-byte marker)
   - `delete`: single object or recursive prefix deletion
   - `rename`: copy+delete for each key in prefix
   - `write_file`: put_object
   - `is_read_only()`: false when authenticated
   - `scheme()`: "s3"
2. All methods are `async` — the `FileSystemProvider` trait methods should
   return `Result<T>` (not `Future`). The caller (`ExplorerPane`) spawns
   on `background_executor`. The trait is sync; S3 calls use
   `tokio::runtime::Handle::current().block_on(...)` or the caller handles
   async dispatch.
   
   **Decision:** Keep the trait sync (matching `list_dir_sync`). S3 provider
   methods use `pollster::block_on` or spawn internally. This avoids
   proliferating async through `ExplorerPane` which is deeply synchronous.

## Key Implementation Notes

### `FileSystemProvider` Trait Sync vs Async

The trait is **synchronous** (methods return `Result<T>`, not `Future`).
Rationale: `ExplorerPane::reload()`, `change_dir()`, `apply_filter()`,
and all file ops are synchronous today. Making them async would require
`async fn` contagion through the entire Explorer pipeline (>10 methods,
>20 call sites). Instead:

- **Local provider**: calls existing sync `list_dir_sync` / `std::fs`.
- **S3 provider**: uses `pollster::block_on(tokio_runtime.spawn(async {...}))`
  internally. S3 calls are spawned onto a background tokio runtime.
- **Path forward**: if latency becomes an issue, `ExplorerPane::reload()` can
  be refactored to spawn on `background_executor` per-operation (already
  done for archive browsing in T004).

### `FileEntryDto` Compatibility

`FileEntryDto` already has a `path: String` field large enough for
`"s3://profile@bucket/prefix/key.jpg"` — no schema change needed.

### `ExplorerPane` Path Validation

When `provider` is `Some`, path validation in `change_dir()` skips
`std::fs::metadata()` checks. The provider's `list_dir` is the authority.

### `aws-sdk-s3` Feature Flags

Minimal features: `behavior-version-latest` (required for v1). No
`rustls`/`native-tls` flag needed — the SDK picks the TLS backend
automatically.
