# In-App Drag and Drop (T051) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `subagent-driven-development` (recommended) or `executing-plans` to implement
> this plan task by task. Use `test-driven-development`, `rust-skills`, `gpui`,
> and `verification-before-completion` where applicable.

**Goal:** Drag the current local-file selection from List or Grid into folder,
cwd, breadcrumb, or other-pane targets, moving by default and copying when Ctrl
is held at drop time.

**Architecture:** A typed `FileDrag` payload and pane-owned targets live in a
focused `explorer/dnd.rs` module. Paste and Drop call one batch-transfer helper
in `chronos_fm_services::fs::ops`, which applies `unique_name` and returns a
structured per-item report. DnD schedules that synchronous service helper on the
background executor, then reloads the participating pane entities without
introducing page-global drag state or a second selection model.

**Tech Stack:** Rust, GPUI/gpui-component typed `on_drag` / `can_drop` /
`drag_over` / `on_drop`, `Entity`/`WeakEntity`, background executor, existing
Chronos-FM filesystem ops and T050 measured item bounds, Root-wrapped
`VisualTestContext`, Hyprland release runtime evidence.

## Global Constraints

- The stamped spec at
  `docs/superpowers/specs/2026-08-10-dnd-in-app-design.md` is authoritative.
- Only local filesystem panes participate; provider-backed panes are no-drop.
- `ExplorerPane::selection` and `selected_paths()` remain the sole selection
  model. Do not use the clipboard as transient drag state.
- Selected item drag carries the whole selection; unselected item drag carries
  only that item and normalizes selection to it.
- Move is default. Resolve Copy from `window.modifiers()` at drop time using
  `control || platform`, not from modifiers at press time.
- Paste and Drop must call the same service batch-transfer helper and the same
  `ops::unique_name` path. Do not duplicate conflict loops.
- Never intentionally overwrite an occupied name. T053 owns future
  Rename/Overwrite/Skip/Apply-to-all UI.
- Keep `move_path` cross-volume copy-plus-delete behavior unchanged.
- Reject the entire target before execution when any payload member is empty,
  self/descendant, non-local, or a same-parent Move.
- Copy into the same parent is valid and produces a unique-name duplicate.
- An invalid item under the pointer must not fall through to the listing cwd.
- DnD filesystem work runs off the UI thread. Reject a second drop while the
  target pane has one pending.
- Reload the source/destination policy from spec §6; never re-enter an entity's
  update callback when source and target are the same pane.
- Starting a file drag cancels T050 marquee state. Do not change marquee
  geometry or selection rules.
- No Source patch is planned. If a GPUI API assumption fails, compile a minimal
  probe against the local `../Source` fork before considering a scoped patch.
- T052 external DnD, T053 conflict UI, T054 undo, T056 progress/cancel queue,
  S3 semantic drops, and spring-loaded folders are out of scope.
- No drive-by formatting or worktree cleanup. Stage by file.
- Executor reports Claim -> Evidence -> Truth base and never self-ACCEPTs.

- [ ] **Step 3: Implement the minimal structured batch helper**

Use owned paths/results so the report can cross the background boundary later:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum TransferMode {
    Copy,
    Move,
}

pub struct TransferSuccess {
    pub source: PathBuf,
    pub destination: PathBuf,
    pub renamed: bool,
    pub move_kind: Option<MoveKind>,
}

pub struct TransferFailure {
    pub source: PathBuf,
    pub error: chronos_fm_core::errors::Error,
}

pub struct TransferReport {
    pub successes: Vec<TransferSuccess>,
    pub failures: Vec<TransferFailure>,
}
```

For each source, derive its single final name, resolve `unique_name` immediately
before the transfer, then call `copy_path` or `move_path`. Never call a raw
`std::fs` mutation from the page layer. Do not implement T053 policies.
