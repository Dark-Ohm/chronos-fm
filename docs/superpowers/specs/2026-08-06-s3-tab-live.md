# T011 — S3 Tab Live: Design Spec

**Status:** Spec (pre-implementation)  
**Source:** `docs/orchestration/tasks/active/T011-s3-tab-live.md`  
**Priority:** P3  
**Scope:** Full S3-compatible file manager via virtual FS + Explorer reuse

## 1. Overview

Replace the S3Page placeholder with a fully functional file manager for
S3-compatible object storage (AWS S3, MinIO, Cloudflare R2, any endpoint).
The Explorer's existing listing/navigation/preview/context-menu machinery is
reused through a `FileSystemProvider` trait, avoiding a parallel implementation.

### 1.1 Design Decisions (from brainstorming)

| Decision | Choice | Rationale |
|---|---|---|
| S3 client | `aws-sdk-s3` (1.x) | Full API: ListObjectsV2, GetObject, PutObject, DeleteObject, HeadObject, multipart upload; pagination built-in; custom endpoint support |
| Scope v1 | Full file manager | Browser-like: navigate buckets/prefixes, list keys, preview, download, upload, delete, context menu |
| Credentials | `config.toml` + `oo7` combo | `config.toml` stores non-secret config (endpoint, region, profile names); `oo7` (system keyring via Freedesktop Secret Service) stores access key + secret key |
| UI architecture | `FileSystemProvider` trait + Explorer reuse | DRY: ~1000+ lines of Explorer code (listing, nav, preview, context menu, properties, selection, keyboard shortcuts, drag-and-drop) applied to S3 without duplication |

### 1.2 Out of Scope (Milestone B+)

- Bucket creation/deletion
- Multipart upload UI (API plumbing included, UI deferred)
- S3 object versioning / lifecycle
- ACL / policy management
- Multiple simultaneous S3 connections
- Presigned URL sharing

## 2. Architecture

### 2.1 `FileSystemProvider` Trait

Lives in `chronos-fm-services::fs::provider` (or `chronos-fm-services::provider`).

```rust
/// Abstract filesystem backend — local disk or S3.
pub trait FileSystemProvider: Send + Sync {
    /// Human-readable label for the root (e.g. "S3" or "/home").
    fn root_label(&self) -> String;

    /// List entries at `path`. `path` is provider-specific:
    /// - Local: absolute filesystem path
    /// - S3: "s3://bucket" or "s3://bucket/prefix/"
    fn list_dir(&self, path: &str, limit: usize, cursor: Option<&str>)
        -> Result<ListResult>;

    /// Read the full contents of a file at `path`.
    fn read_file(&self, path: &str) -> Result<Vec<u8>>;

    /// Check existence + metadata of a single entry.
    fn metadata(&self, path: &str) -> Result<FileEntryDto>;

    /// Create a directory-like prefix. For S3 this is a zero-byte object
    /// ending in "/" (or a no-op — S3 has no real directories).
    fn create_dir(&self, parent: &str, name: &str) -> Result<()>;

    /// Delete an entry: file or "directory" (recursive key deletion for S3).
    fn delete(&self, path: &str, is_dir: bool) -> Result<()>;

    /// Rename/move an entry. For S3 "directories": copy+delete all prefixed keys.
    fn rename(&self, from: &str, to: &str) -> Result<()>;

    /// Upload file content to `path`. For S3 this is PutObject.
    fn write_file(&self, path: &str, content: &[u8]) -> Result<()>;

    /// Whether this provider supports write operations (upload, delete, rename).
    /// Read-only mode when credentials are missing or invalid.
    fn is_read_only(&self) -> bool;

    /// Scheme prefix for paths, e.g. "s3" or "file".
    fn scheme(&self) -> &str;
}
```

**Key design points:**

- `path` strings encode the backend implicitly through a scheme prefix or
  the provider that holds them. The trait is deliberately opaque: callers
  never parse provider paths — they pass them through.
- `list_dir` reuses the existing `ListParams`/`ListResult` types from
  `chronos-fm-services::fs::listing`. No new DTO.
- `read_file` returns `Vec<u8>` — the Explorer's preview pipeline already
  handles `Vec<u8>` for text/images.
- `is_read_only()` controls whether the context menu shows Upload/Delete/Rename
  entries.
- The trait is `Send + Sync` so it can live in an `Arc` and be dispatched
  from the background executor (network I/O) without blocking the UI.

### 2.2 Local FS Adapter

`LocalFileSystemProvider` wraps the existing `list_dir_sync`/`fs::ops`
functions. This is the default provider for `ExplorerPane` with `None` —

- `list_dir` delegates to `list_dir_sync`
- `read_file` delegates to `std::fs::read`
- `metadata` delegates to `std::fs::symlink_metadata`
- `create_dir` / `delete` / `rename` / `write_file` delegate to
  `chronos-fm-services::fs::ops`
- `is_read_only()` returns `false`

### 2.3 S3 Provider

`S3FileSystemProvider` wraps `aws_sdk_s3::Client`.

#### 2.3.1 Path Model

S3 paths use the scheme `s3://<profile>@<bucket>/<key>`:

| Path | Meaning |
|---|---|
| `s3://default@my-bucket/` | Root of bucket `my-bucket` under the default profile |
| `s3://default@my-bucket/photos/` | Prefix `photos/` |
| `s3://default@my-bucket/photos/beach.jpg` | Object key `photos/beach.jpg` |
| `s3://default@` | Bucket listing (root of S3) |

The `profile` maps to a `[s3.profiles.<name>]` section in `config.toml` with
endpoint + region fields; credentials are fetched from `oo7` keyring under
`chronos-fm-s3/<profile>`.

#### 2.3.2 Operations

- **`list_dir("s3://default@")`**: `client.list_buckets()` → fake entries
  with `kind = "dir"`.
- **`list_dir("s3://default@bucket/prefix/")`**: `client.list_objects_v2()
  .bucket("bucket").prefix("prefix/").delimiter("/")` →
  `CommonPrefixes` become `kind = "dir"` entries; `Contents` become
  `kind = "file"` entries.
- **`read_file("s3://default@bucket/key")`**: `client.get_object()
  .bucket("bucket").key("key")` → collect body bytes.
- **`metadata(...)`**: `client.head_object()` for files,
  synthetic for "dirs".
- **`write_file(...)`**: `client.put_object()` with `ByteStream`.
- **`delete(path, is_dir=true)`**: `list_objects_v2` with paginator +
  `delete_objects` batch (careful: delete ALL prefixed keys).
- **`rename(from, to, is_dir=true)`**: copy+delete loop over all
  prefixed keys.
- **`create_dir(parent, name)`**: no-op for S3 (directories are virtual).
  Optionally create a zero-byte `<prefix>/` marker object.

#### 2.3.3 Credential Lifecycle

1. On startup / config reload: read `[s3.profiles.<name>]` from `config.toml`
   for `endpoint`, `region`, `force_path_style`.
2. For each profile, try `oo7::Keyring::new()` to retrieve `access_key_id`
   and `secret_access_key` stored under `chronos-fm-s3/<profile>`.
3. If both found → build `aws_sdk_s3::Client`. If not → profile is
   "unauthenticated": the UI shows a "Configure credentials" prompt in the
   S3 tab instead of a file listing.
4. On first successful save of credentials (from the S3 tab's settings card):
   store secrets in `oo7`, rebuild client, switch to listing mode.
5. Credential errors (403 Forbidden, expired tokens) surface in the
   explorer's status bar.

## 3. Configuration Schema

### 3.1 `config.toml` Additions

```toml
[s3]
default_profile = "personal"   # which profile to use by default

[s3.profiles.personal]
endpoint = "https://s3.amazonaws.com"
region = "us-east-1"
force_path_style = false

[s3.profiles.minio]
endpoint = "http://localhost:9000"
region = "us-east-1"
force_path_style = true
```

### 3.2 `ConfigField` Extensions

Add variants to the `ConfigField` enum in `patch.rs`:
- `S3DefaultProfile(String)`
- `S3ProfileEndpoint { profile: String, endpoint: String }`
- `S3ProfileRegion { profile: String, region: String }`
- `S3ProfileForcePathStyle { profile: String, value: bool }`

### 3.3 Keyring Schema

| Keyring service | Account | Content |
|---|---|---|
| `chronos-fm-s3/personal` | `access_key_id` | `AKIA...` |
| `chronos-fm-s3/personal` | `secret_access_key` | `wJalr...` |

`oo7::Keyring::new()` auto-selects the best available backend (Secret Service
D-Bus, fallback to encrypted file storage if no D-Bus daemon).

## 4. Explorer Refactoring

### 4.1 `ExplorerPane` Changes

Add one field:
```rust
/// Optional virtual FS backend. When `None`, the pane falls back to local
/// filesystem operations (the existing code path).
pub provider: Option<Arc<dyn FileSystemProvider>>,
```

The `reload()` method becomes:

```rust
fn reload(&mut self) {
    self.loaded = true;
    let result = if let Some(provider) = &self.provider {
        provider.list_dir(&self.cwd, config::DIR_LISTING_LIMIT, None)
    } else {
        list_dir_sync(ListParams { path: &self.cwd, limit: ..., cursor: None })
    };
    // ... same entries/sort/filter logic
}
```

The `activate_entry()` method for preview reading:
```rust
if item.kind == "dir" {
    self.change_dir(item.path, window, cx);
} else {
    // For preview: read_file via provider or local fs
    self.open_preview(item.path, window, cx);
}
```

### 4.2 What Does NOT Change

- **Listing rendering** (`grid.rs`, `row.rs`, `list.rs`): unchanged. They
  receive `FileEntryDto` objects regardless of backend.
- **Sorting/filtering** (`entries.rs`, `apply_filter()`): unchanged.
- **Navigation history** (`navigation.rs`): unchanged. Push/pop `cwd` strings.
- **Context menu**: unchanged. Actions delegate to provider when present.
- **Properties dialog**: unchanged.
- **Preview**: unchanged. The preview pipeline already reads file content
  and detects MIME types.
- **Selection, keyboard navigation, drag-and-drop**: unchanged.
- **Split-view, tabs, session restore**: unchanged.

### 4.3 File Operations Through Provider

File ops (`file_ops.rs`: delete, rename, new folder, copy/paste) are
extended with a provider dispatch:

```rust
fn delete_entry(&mut self, ...) {
    if let Some(provider) = &self.provider {
        // Async: spawn on background executor
        let provider = provider.clone();
        cx.spawn_in(window, |this, cx| async move {
            provider.delete(&path, is_dir).await?;
            this.update_in(&cx, |this, cx| { this.reload(); cx.notify(); })
        }).detach();
    } else {
        // Existing synchronous local FS delete
        fs::ops::delete(&path)?;
        self.reload();
    }
}
```

## 5. S3Page UI

### 5.1 Layout

The S3 tab hosts an embedded `ExplorerPage` (or a single `ExplorerPane`
with an S3 provider):

```
┌──────────────────────────────────────────────┐
│ ☁️ S3 — personal (s3.amazonaws.com)    [⚙]  │  ← header card
├──────────────────────────────────────────────┤
│ [sidebar] │  Buckets / Prefixes / Keys        │  ← standard Explorer
│  • bucket1 │  ┌──────────────────────────┐   │
│  • bucket2 │  │ photos/         [dir]    │   │
│            │  │ beach.jpg   2.1MB [file]  │   │
│            │  │ sunset.jpg  1.8MB [file]  │   │
│            │  └──────────────────────────┘   │
├──────────────────────────────────────────────┤
│ s3://personal@my-bucket/photos/ │ 2 items     │  ← footer
└──────────────────────────────────────────────┘
```

### 5.2 States

| State | UI |
|---|---|
| No profiles configured | "Add an S3 profile in Settings → S3" card + button linking to `settings.rs` S3 section |
| Profile exists, no credentials | "Enter your access key" card with Input fields + Save button → stores in oo7 |
| Authenticated, listing | Full Explorer pane with S3 provider |
| Auth error (403) | Status bar: "Authentication failed for profile 'X' — check credentials" |
| Network error | Status bar: "Cannot reach s3.amazonaws.com — check connection" |

### 5.3 Header Card

```
☁️ S3 — Profile: personal  (s3.amazonaws.com)   [Refresh] [Upload]
```

- Profile dropdown: switch between configured profiles
- Refresh: re-list current path
- Upload: file picker → PutObject
