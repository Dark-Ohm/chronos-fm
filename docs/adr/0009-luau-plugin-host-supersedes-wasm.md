# 0009 — Plugin host: Luau (chronos_luau), не WASM Component Model — заменяет ADR 0005

> Статус: Accepted
> Дата: 2026-07-18
> Заменяет: [ADR 0005](./0005-wit-bindgen-component-model.md)

## Контекст

ADR 0005 (2026-05-28) закрепил wit-bindgen + WASM Component Model
(wasmtime 30+, WASI Preview 2) для plugin-host P4, мотивация —
мультиязычные плагины (Rust / TypeScript / Python).

С тех пор (2026-07-18, брейнсторм-сессия с Архитектором):

- `chronos-fm-plugin-host` (P4) до сих пор **не реализован** — ни
  строчки кода. Мигрировать нечего — это решение на бумаге, не
  переписывание.
- Chronos-FM и ChronOS (`../ChronOS`, сиблинг-репо, тот же автор)
  объединены на один GPUI-тулкит (`../Source`, см. `GROK.md`/
  `HANDOFF.md` §2) — принцип пользователя: «один тулкит на всё, иначе
  не умно». Та же логика распространяется на плагинный рантайм: в
  ChronOS уже есть боевой sandboxed Luau-рантайм (`chronos_luau` —
  mlua/LuauJIT, VM на плагин, capability-gated API-таблица, hot-reload
  через inotify, tick-цикл на GPUI executor), в продакшене с 2026-07-09
  (виджеты бара, лаунчер, tray-плагины).
- Пользователь не хочет тянуть веб-смежный тулчейн в плагинный флоу:
  TypeScript-шаблон из ADR 0005 зависит от `jco`/`componentize-js`
  (npm/Node.js) — явно нежелательно в этом проекте, независимо от
  самого wasmtime (который сам по себе не веб-технология).
- Мультиязычная заявка WASM Component Model (Rust/TS/Python) была
  дифференциатором в исходном README, но ни один пользователь/автор
  плагина сейчас на неё не полагается — отмена ничего не стоит сегодня.

## Решение

**Отменить WASM Component Model / wasmtime для plugin-host. Взять
`chronos_luau` (уже существующий sandboxed Luau-рантайм ChronOS) как
общую зависимость — унифицировать плагинную историю между проектами
так же, как унифицирован GPUI-тулкит.**

- Рантайм: `mlua` + LuauJIT, отдельная `Lua` VM на плагин (как в
  `chronos_luau`).
- Sandbox: capability-gated таблица `chronos.*` (`fs`, `spawn`,
  `network`, `ipc` по манифесту), `unsafe = true` TOFU-лазейка для
  first-party плагинов — та же модель, что в ChronOS.
- Hot-reload: inotify watcher, тот же механизм, что в ChronOS.
- Никакого WIT, wit-bindgen, wasmtime-wasi, отдельного
  tokio-runtime-изоляции для исполнения плагинов (цель ADR 0004 —
  убрать tokio из ядра приложения — теперь только ЛЕГЧЕ достижима:
  Luau через GPUI executor не требует отдельного tokio-рантайма
  вообще, в отличие от wasmtime-wasi).
- Языки: только Lua/Luau. Никаких Rust/TypeScript/Python
  component-плагинов. Шаблоны `plugin-template-rust`/`-typescript`/
  `-python` из плана ADR 0005 отменены, не строятся.
- Конкретный открытый хвост (не начато, задание не заведено): решить,
  становится ли `chronos_luau` общим крейтом через path-dep из ChronOS
  (по аналогии с унификацией GPUI-тулкита), или Chronos-FM держит свою
  копию. Склоняюсь к общему крейту — та же логика, что у GPUI-решения —
  но не решено; не начинать работу над `chronos-fm-plugin-host` без
  этого решения.

## Последствия

### Плюсы

- Нулевая цена миграции — под ADR 0005 ничего не построено.
- Переиспользуется закалённый, уже работающий sandbox вместо
  строительства второго с нуля (wasmtime + WASI Preview 2 + WIT host —
  по собственной оценке ADR 0005, недели работы).
- Единая плагинная история на оба сиблинг-проекта — автор плагина,
  знающий `chronos.*` для ChronOS, уже знает API Chronos-FM.
- Не нужно гнаться за API-дрейфом wasmtime/wit-bindgen между релизами
  (собственный минус ADR 0005).
- Никакого npm/Node.js тулчейна нигде в плагинном флоу.

### Минусы

- Теряется мультиязычная заявка Rust/TypeScript/Python — это реальное
  изменение позиционирования из исходного README, не просто деталь
  реализации. Если community/маркетинговый фрейминг был важен — это
  цена, пользователь принял этот компромисс осознанно.
- Lua/Luau-плагины не могут переиспользовать более широкую
  WASM-component-экосистему (например, взять готовый Rust
  WASM-компонент как зависимость плагина) — плагины всегда
  самописный Luau.
- Граница memory-safety sandbox теперь «Luau VM + capability-gated
  API-таблица» (через mlua), не WASM linear-memory изоляция. Совпадает
  с уже принятым риск-профилем ChronOS — не новый риск, унаследованный.

## Рассмотренные альтернативы

| Вариант | Почему отклонён |
|---|---|
| Оставить ADR 0005 (wit-bindgen + Component Model) | Больше не служит цели «один тулкит, одна экосистема» теперь, когда ChronOS и Chronos-FM делят GPUI-форк; дублирует sandbox-работу, уже решённую `chronos_luau` |
| Extism (изначально отклонённый MVP-путь ADR 0005) | Всё ещё второй, никак не связанный sandbox/рантайм рядом с `chronos_luau` — та же проблема дублирования, что и с wasmtime |
| Убрать плагины совсем | Не запрошено; отменена мультиязычная заявка, не сама плагинная система |
